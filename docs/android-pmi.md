# Программа и методика испытаний Android-клиента Test-DPLS

## 1. Средства испытаний

- минимум два устройства Test-DPLS с различными ID;
- С2000-КДЛ и подключённые адресные устройства;
- телефоны или эмуляторы Android API 26, 30, 31, 33 и 35;
- debug APK из GitHub Actions и подписанный release APK;
- средство измерения напряжения ДПЛС и резервного питания.

## 2. Предварительные автоматические проверки

Workflow должен завершить успешно:

```text
Firmware host tests
Android build, tests and lint
Android requirements contract
```

Скачать artifacts с APK/AAB и отчётами. SHA проверяемого commit фиксируется в протоколе испытаний.

## 3. Функциональные испытания

| № | Действие | Ожидаемый результат |
|---|---|---|
| 1 | Установить APK на API 26/30/31/33/35 | приложение запускается без crash |
| 2 | Отказать в разрешении, затем открыть системные настройки | приложение объясняет проблему и даёт переход в настройки |
| 3 | Запустить поиск при двух Test-DPLS и посторонних BLE | отображаются только Test-DPLS, есть ID, RSSI и ручной выбор |
| 4 | Остановить поиск вручную и дождаться 60 с | сканирование прекращается в обоих случаях |
| 5 | Нажать «Показать на объекте» | выбранное устройство мигает, UI показывает countdown, остановка ≤60 с |
| 6 | Подключиться к недоступному устройству | попытка завершается ошибкой не позднее 10 с |
| 7 | Подключиться к новому устройству | запрашиваются имя, пароль и повтор; неверный формат не принимается |
| 8 | Выполнить пять неверных входов | устройство возвращает блокировку, ввод отключён, countdown около 300 с |
| 9 | Проверить каждый тестовый режим | есть предупреждение и подтверждение; UI показывает только состояние из устройства |
| 10 | Отключить Bluetooth в тестовом режиме | устройство возвращается в «Норма» в пределах требования прошивки |
| 11 | Оставить тестовый режим на 5 минут | устройство автоматически возвращается в «Норма» |
| 12 | Ухудшить радиосвязь | числовой и графический RSSI обновляются, появляется «Слабая связь» |
| 13 | Загрузить журнал 200 записей | отображаются sequence, время, тип и параметр |
| 14 | Разорвать связь во время журнала | приложение восстанавливает связь или выдаёт понятную ошибку без порчи данных |
| 15 | Сохранить и отправить CSV/TXT | имя содержит ID, дату и время; UTF-8 корректно открывается |
| 16 | Сменить имя и пароль | изменения подтверждаются устройством и сохраняются после reconnect |
| 17 | Открыть «Об устройстве и приложении» | показаны версии приложения/протокола/прошивки и OSS |
| 18 | Сделать screenshot и открыть recent apps на экране пароля | содержимое скрыто системой (`FLAG_SECURE`) |
| 19 | Переключить системную тему и увеличить шрифт до 130% | интерфейс остаётся читаемым и управляемым |
| 20 | Повернуть телефон | Activity остаётся в портретной ориентации |

## 4. Критерий завершения

- все GitHub Actions зелёные;
- нет дефектов, способных включить неверный режим или скрыть фактическое состояние;
- все пункты 1–20 имеют фактический результат, модель телефона, версию Android и ссылку на фото/лог;
- release APK подписан отдельным production keystore и проверен `apksigner verify`.
