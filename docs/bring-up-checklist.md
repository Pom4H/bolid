# Чеклист bring-up Тест-ДПЛС · hardware revision 2

Этот документ описывает **текущую** аппаратную модель прошивки. Источник истины
для распиновки — `Firmware/phy6252/dpls_board.h`; CI дополнительно проверяет её
`tools/check_phy6252_contract.py`. Если код и этот документ расходятся, релиз
должен быть заблокирован.

## 0. Перед прошивкой

```sh
cmake -S Firmware -B Firmware/build
cmake --build Firmware/build
ctest --test-dir Firmware/build --output-on-failure
python3 tools/check_phy6252_contract.py

# целевая сборка SDK 3.1.2 / Arm Compiler 6
tools/build_firmware.sh tmp/test-dpls-sdk-3.1.2.hex
```

После прошивки:

- плата загружается без watchdog-loop;
- BLE `Test-DPLS-XXXX` появляется в сканировании;
- при reset ни один управляющий светодиод стенда не даёт краткой вспышки;
- до команды режима все шесть управляющих выходов = 0.

## 1. Фиксированная распиновка rev.2

Силовые выходы:

- ISO: **P31 / P32 / P33** = ISO_1 / ISO_2 / ISO_T;
- KZ: **P14 / P16 / P17** = KZ_1 / KZ_2 / KZ_T.

Измерение напряжений:

- **+1=P20** → ADC_CH9;
- **+2=P15** → ADC_CH4;
- **+T=P24** → ADC_CH2;
- **резерв=P23** → ADC_CH1.

Служебные выводы:

- RGB кита: red=P07, green=P11, blue=P18;
- физический factory reset: **P34**;
- P00 прошивкой rev.2 не используется.

Ни один из физических GPIO выше не должен одновременно иметь две разные роли.
Исключение только символическое: `DPLS_PIN_LINE_ADC` — legacy-алиас `PORT1_ADC`,
то есть тот же +1/P20, а не отдельный вход.

## 2. Шесть управляющих выходов

Проверять логическим анализатором и/или шестью отдельными LED стенда:

| Режим | P31 ISO_1 | P32 ISO_2 | P33 ISO_T | P14 KZ_1 | P16 KZ_2 | P17 KZ_T |
|---|---:|---:|---:|---:|---:|---:|
| Норма | 0 | 0 | 0 | 0 | 0 | 0 |
| Обрыв +T | 0 | 0 | **1** | 0 | 0 | 0 |
| Обрыв магистрали | 0 | **1** | 0 | 0 | 0 | 0 |
| КЗ +1 | 0 | 0 | 0 | **1** | 0 | 0 |
| КЗ +2 | 0 | 0 | 0 | 0 | **1** | 0 |
| КЗ +T | 0 | 0 | 0 | 0 | 0 | **1** |

Проверки:

- [ ] холодный старт: все 0;
- [ ] warm reset из каждого режима: ни один выход не вспыхивает перед Norma;
- [ ] каждый режим активирует ровно один GPIO;
- [ ] переход режим→режим выполняется break-before-make — нет перекрытия двух `1`;
- [ ] disconnect, session timeout, mode timeout, low reserve и critical fault
      возвращают все шесть GPIO в 0;
- [ ] 50–100 циклов `режим → Norma → другой режим` без зависания выхода.

## 3. P16/P17 и 32 kHz

P16/P17 у PHY6252 также являются XTAL_32K_IN/OUT. На этой плате внешний 32.768
kHz кварц отсутствует, используется RC32K, а P16/P17 являются KZ_2/KZ_T.
`dpls_phy6252_hw.c` поэтому:

1. снимает XTAL bias сразу после vendor `hal_init()`;
2. восстанавливает это состояние wake callback'ом;
3. запрещает sleep на время активного BLE-соединения тем же `MOD_USR1`.

Проверить отдельно:

- [ ] P16/P17 не дают коротких импульсов при BLE connect/disconnect;
- [ ] P16/P17 не меняют уровень сами по себе во время 10–15 минут соединения;
- [ ] после disconnect устройство снова может уходить в low-power и затем
      корректно рекламироваться/подключаться;
- [ ] осциллографом проверить reset и wake — глаз/LED не ловит микросекундные пики.

## 4. BLE + sleep-lock

Известная историческая проблема: ADC clock setup, совпадающий со sleep/wake между
BLE connection events, приводил к OSAL/GATT freeze/watchdog. В rev.2 соединение
без успешного `MOD_USR1` lock считается небезопасным: прошивка возвращает Norma
и разрывает link вместо продолжения работы с no-op lock.

- [ ] держать BLE подключённым не менее 15 минут;
- [ ] приложение запрашивает состояние примерно раз в секунду;
- [ ] одновременно менять все четыре ADC-входа;
- [ ] нет disconnect, watchdog reset, зависшего STATE_REPORT;
- [ ] измерить ток **во время соединения**: sleep там намеренно отключён;
- [ ] отдельно измерить advertising/disconnected ток: там sleep разрешён.

## 5. Четыре ADC-канала

Сканер владеет ADC целиком и запускает только один канал одновременно. Новый
цикл стартует после завершения предыдущего, поэтому зависший/медленный цикл не
может быть перезаписан очередным секундным tick.

Ожидаемый порядок одного цикла:

1. +1 / P20 / ADC_CH9;
2. +2 / P15 / ADC_CH4;
3. +T / P24 / ADC_CH2;
4. резерв / P23 / ADC_CH1.

Ошибка одного преобразования не блокирует следующие каналы: проблемный вход
пропускается до следующего цикла. Измерение, которое давно не обновлялось,
перестаёт считаться valid; замороженное старое число не должно выглядеть живым.

- [ ] вращать каждый потенциометр отдельно — меняется только соответствующее поле;
- [ ] +1 не изменяет +2/+T/резерв и наоборот;
- [ ] все четыре значения обновляются непрерывно;
- [ ] отключить один аналоговый провод: остальные три продолжают обновляться;
- [ ] после потери свежих samples UI должен показать канал как невалидный/`—`,
      а не бесконечно держать старое число;
- [ ] прогон ADC + BLE ≥2 ч без watchdog/GATT freeze.

## 6. Делители и калибровка

Три входа ДПЛС имеют отдельные физические делители и **отдельные runtime
калибровки**. Номинал до заводской калибровки — gain 31.000, offset 0.
Одна измеренная коррекция P20 больше не копируется на +2 и +T.

Резерв — другой электрический тракт. Для него номинальный gain пока 2.000 и
отдельные sanity bounds; это предварительное значение до измерения силовой
платы.

SNV `0x83` понимает два формата:

- legacy v1: одна line calibration + reserve. При миграции line correction
  применяется только к +1/P20; +2/+T остаются nominal, потому что перенос чужой
  поправки создавал бы ложную точность;
- v2: четыре независимых `{gain, offset}` — +1, +2, +T, reserve, с version+CRC.

Флаг `ADC_CALIBRATED` выставляется только когда присутствует корректная v2
калибровка **всех четырёх** входов.

- [ ] снять минимум две эталонные точки для каждого +1/+2/+T отдельно;
- [ ] добиться требуемой погрешности на каждом входе, а не только на +1;
- [ ] определить фактический divider reserve и заменить предварительный 2.000;
- [ ] после записи v2 перепроверить 5, 10, 20, 27 В на каждом DPLS-входе;
- [ ] без v2 приложение не должно заявлять весь ADC как откалиброванный.

## 7. Источник питания и low reserve

Логика источника питания использует свежий +1/P20 с гистерезисом:

- LINE → RESERVE ниже 3.0 В;
- RESERVE → LINE выше 4.0 В.

Предварительные пороги резерва:

- low <3.7 В;
- clear >4.0 В.

Если резервное измерение устарело/невалидно, управление выбирает fail-safe
направление: новый тестовый режим не должен продолжаться на основании старого
«резерв нормальный».

- [ ] снять линию → `power_source=RESERVE`;
- [ ] восстановить линию → `power_source=LINE`;
- [ ] медленно пройти оба порога и убедиться, что нет дребезга;
- [ ] при low reserve активный тест возвращается в Norma;
- [ ] проверить автономию и ток на реальной силовой плате.

## 8. Factory reset

Factory reset rev.2 находится на **P34**, потому что P24 занят измерением +T.

- [ ] активировать физический reset на P34 согласно разводке стенда/платы и
      удерживать ≥5 с;
- [ ] имя/пароль/бонды очищены, прибор снова требует commissioning;
- [ ] удалённой команды factory reset нет;
- [ ] P24 при этом продолжает оставаться только ADC +T.

## 9. RGB identify

Встроенный RGB не является индикатором силовых режимов. Текущая сцена — только
«показать прибор»: зелёный P11, красный P07 и синий P18 принудительно держатся в
0, чтобы retained state не смешивал цвет.

- [ ] identify мигает зелёным;
- [ ] красный/синий при identify не зажигаются;
- [ ] вне identify RGB погашен;
- [ ] reset из identify не оставляет краткой цветной вспышки.
