# Чеклист bring-up Тест-ДПЛС (этап 7)

Проверка софта на реальном железе: сначала на плате PB-03F-Kit (BLE, светодиод,
логика, ADC через внешний делитель), затем на макете/опытном образце силовой
части (ключи ISO/KZ, резервный ионистор, автоизоляция). Всё, что до этого этапа
собиралось и проходило хостовые тесты, но **не проверялось на железе**, сведено
сюда. Пункты с ⚠ содержат плейсхолдеры в коде, которые калибруются здесь.

Ссылки на код: распиновка — `Firmware/phy6252/dpls_board.h`; ADC/питание/резерв/
автоизоляция — `Firmware/phy6252/dpls_phy6252_app.c`; калибровка — `Firmware/src/
dpls_calib.c`; светодиод — `Firmware/src/dpls_led.c`; пороги/константы — вверху
`dpls_phy6252_app.c`.

## 0. Подготовка

```sh
# сборка ядра + хостовые тесты (должны быть зелёными до выезда на железо)
cmake -S Firmware -B Firmware/build && cmake --build Firmware/build
ctest --test-dir Firmware/build --output-on-failure

# полная прошивка → tmp/test-dpls.hex
tools/build_firmware.sh

# прошивка платы (KEY1: зажать, запустить, отпустить на «Turn on the power»)
tools/flash_firmware.sh tmp/test-dpls.hex          # без --erase: SNV сохраняется
tools/flash_firmware.sh tmp/test-dpls.hex --erase  # чистая плата (стирает журнал/пароль/калибровку)

# UART-лог загрузки (короткое нажатие KEY1 для рестарта)
python3 tools/serial_capture.py 20 --no-reset
```

- [ ] Плата стартует, watchdog (2 с) не перезагружает в цикле; в логе виден нормальный boot.
- [ ] Реклама BLE `Test-DPLS-XXXX` видна, приложение подключается и аутентифицируется.

## 1. Силовые выходы режимов (макет силовой части)

Проверять логическим анализатором/вольтметром на P31/P32/P33 (ISO) и P14/P16/P17 (KZ).
Ожидаемое соответствие (активный «1»):

| Режим | ISO_1 P31 | ISO_2 P32 | ISO_T P33 | KZ_1 P14 | KZ_2 P16 | KZ_T P17 |
|---|---|---|---|---|---|---|
| Норма | 0 | 0 | 0 | 0 | 0 | 0 |
| Обрыв +Т | 0 | 0 | **1** | 0 | 0 | 0 |
| Обрыв магистрали | 0 | **1** | 0 | 0 | 0 | 0 |
| КЗ +1 | 0 | 0 | 0 | **1** | 0 | 0 |
| КЗ +2 | 0 | 0 | 0 | 0 | **1** | 0 |
| КЗ +Т | 0 | 0 | 0 | 0 | 0 | **1** |

- [ ] На старте (до BLE) все шесть выходов = 0.
- [ ] Каждый режим из приложения даёт ровно один активный сигнал по таблице.
- [ ] Break-before-make: при переходе между режимами нет момента с двумя активными выходами (смотреть анализатором на переключении, особенно KZ→KZ).
- [ ] Переключение ≤1 с (ТЗ 4.3.6).
- [ ] КЗ регистрируется на С2000-КДЛ как «Короткое замыкание ДПЛС»; обрывы — как «Нет связи»; после «Нормы» линия восстанавливается без повреждений (ТЗ 5.1).
- [ ] Сквозное сопротивление в «Норме» ≤40 мОм; ток КЗ ≤1 А (ТЗ 4.3.3/4.3.5) — измеряется на силовой части.

## 2. Светодиод (P7, световод корпуса)

Тайминги в `dpls_led.h`: короткая 150 мс / пауза 250 мс / длинная 800 мс /
межсерийная 1,6 с. Проверять глазом/осциллографом по каждой сцене.

- [ ] Норма (питание от линии) — светодиод выключен.
- [ ] КЗ+1 / КЗ+2 / КЗ+Т — 1 / 2 / 3 коротких вспышки, повтор через 1,6 с.
- [ ] Обрыв магистрали — длинная + 2 коротких; Обрыв +Т — длинная + 3 коротких.
- [ ] Идентификация («Показать на объекте») — 1 Гц, скважность 50 %, авто-стоп ≤60 с.
- [ ] Питание от резерва — сдвоенный «тик» в паузе (в «Норме» раз в 3 с).
- [ ] Автоизоляция реального КЗ — постоянное свечение.
- [ ] Приоритет: идентификация перекрывает автоизоляцию; автоизоляция перекрывает индикацию режима.

## 3. ⚠ Измерение напряжения линии (P20/ADC9)

Подать на вход измерительного тракта известные напряжения (или через штатный
делитель 3,0 МОм/100 кОм) от источника, сверять с поверенным вольтметром.

- [ ] Отображаемое напряжение растёт монотонно и в разумных пределах во всём диапазоне 0…30 В.
- [ ] **Проверить режим ADC**: сейчас стоит обычное разрешение (не high-res), т.к. high-res режим обрезает ~0,8 В, а пин при 30 В ≈0,97 В. Убедиться, что при 27–30 В нет клиппинга/насыщения.
- [ ] **Двухточечная калибровка**: снять две точки (напр. 5 В и 27 В), вычислить gain+offset. Солвер `dpls_calib_from_two_points` уже готов и протестирован; занести результат в SNV `0x82` (см. п. 7 — канал занесения).
- [ ] После калибровки: погрешность ≤±0,1 В в 5…27 В, дискретность 0,1 В (ТЗ 4.3.7); сверка с поверенным вольтметром по среднему значению (ТЗ 5.1f).
- [ ] Дефолт (без калибровки) даёт разумное значение (gain 1/31) — деградация мягкая.

## 4. ⚠ Резервный ионистор (P23/ADC1) и источник питания

Плейсхолдеры в коде: `DPLS_VCAP_NOMINAL_GAIN_MILLI=2000` (делитель VCAP неизвестен —
в схеме Э3 его нет), пороги `DPLS_RESERVE_LOW_MV=3700`/`OK=4000`,
`DPLS_LINE_ABSENT_MV=3000`/`PRESENT=4000`.

- [ ] Определить фактический делитель VCAP по схеме опытного образца, задать `vcap` gain (и при необходимости калибровку в SNV).
- [ ] Проверить показание напряжения резерва в рабочем окне ионистора (~5,0→3,6 В).
- [ ] Порог «низкий резерв»: подстроить `DPLS_RESERVE_LOW_MV/OK` под нижнюю границу окна; убедиться, что флаг не дребезжит (гистерезис).
- [ ] Отбор линии: при снятии питания линии устройство переходит на резерв, `power_source`=RESERVE, событие журнала 12; при восстановлении — обратно.
- [ ] Автономия от резерва ≥5 мин с управлением по BLE (ТЗ 4.4.2, 5.1d).
- [ ] Средний ток ≤0,5 мА, пики ≤3 мА (ТЗ 4.3.2) — измерить; сэмплирование ADC раз в ~1 с в бюджете.
- [ ] Автовозврат в «Норму» при низком резерве (ядро форсит) — проверить в тестовом режиме на разряжающемся ионисторе.

## 5. ⚠ Автоизоляция реального КЗ (силовая часть)

Детект в прошивке — только по просадке линии в режиме «Норма» (порог
`DPLS_AUTOISO_TRIP_MV=3000`, снятие `4500`, гейт «сначала увидеть здоровую линию»).
Быстрая изоляция ≤200 мс — аппаратная, проверяется отдельно на силовой части.

- [ ] Реальное КЗ ниже по линии → аппаратная изоляция срабатывает ≤200 мс, порог 2,9–3,4 В (как БРИЗ-Т, РЭ).
- [ ] Прошивка фиксирует: событие журнала 14 (param 1), светодиод — постоянное свечение, в приложении баннер «Автоизоляция реального КЗ».
- [ ] Приоритет: при активной автоизоляции команда входа в тестовый режим отклоняется (в приложении «Команда отклонена: активна автоизоляция реального КЗ», код 5).
- [ ] Снятие КЗ → линия восстановлена, событие 14 (param 0), светодиод гаснет, тесты снова доступны.
- [ ] Подтвердить пороги (3000/4500 мВ) на реальной просадке; при необходимости скорректировать.
- [ ] **Открытый вопрос:** дискретного входа «изоляция активна» в распиновке нет. Если схемотехник выведет такой сигнал на резервный пин (P11/P15/P18/P34), детект станет надёжнее и заработает во всех режимах, а не только в «Норме».

## 6. Заводской сброс пароля (P24)

- [ ] Перемычка P24↔GND, удержание ≥5 с → пароль/имя сброшены, устройство `EMPTY`, требует нового пароля; событие/поведение как в `clear_settings_and_bonds`.
- [ ] Удалённый сброс по BLE невозможен (ТЗ 7.3.7, 5.1h).
- [ ] Пароль/настройки/калибровка сохраняются при переключениях питания (ТЗ 4.4.5).

## 7. Канал занесения заводской калибровки (реализовать здесь)

Двухточечный солвер (`dpls_calib_from_two_points`) и NV-хранилище (SNV `0x82`,
`dpls_calib_nv_t`) готовы. Отсутствует только вход для занесения. Предложено —
UART-сервисная команда (плата имеет UART, RX0/TX0), т.к.:
- калибровка — заводская/сервисная операция, не операторская (ТЗ её в приложение не выносит);
- требует физического доступа и эталонного источника/вольтметра.

- [ ] Реализовать разбор сервисной UART-команды: «две точки (line_mv, pin_raw) → gain+offset → запись в SNV `0x82` с CRC», плюс чтение текущей калибровки.
- [ ] Альтернатива при необходимости — защищённая BLE-команда только для сервисного режима; согласовать с Заказчиком.
- [ ] После занесения — перепроверить п. 3 (±0,1 В).
