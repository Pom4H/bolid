# Hardware bring-up и приёмка Test-DPLS

Чеклист проверки на реальном железе: сначала PB-03F-Kit (boot, BLE, LED, логика и ADC), затем макет/опытный образец силовой части (ISO/KZ, резерв, измерения и автоизоляция). Пункты с ⚠ требуют измерения или калибровки на конкретной силовой части и не должны считаться подтверждёнными только по host-тестам.

Исходники: распиновка — `firmware/phy6252/dpls_board.h`; ADC/питание/резерв/автоизоляция — `firmware/phy6252/dpls_phy6252_app.c`; калибровка — `firmware/src/dpls_calib.c`; светодиод — `firmware/src/dpls_led.c`.

## 0. Подготовка

```sh
# portable core + host tests
cmake -S firmware -B firmware/build
cmake --build firmware/build
ctest --test-dir firmware/build --output-on-failure
bash tools/lint_firmware.sh
bash tools/coverage_firmware.sh

# target builds
tools/build_firmware.sh keil tmp/test-dpls.hex
tools/build_firmware.sh gcc tmp/test-dpls-gcc.hex

# flashing: without --erase SNV survives
tools/flash_firmware.sh tmp/test-dpls.hex
tools/flash_firmware.sh tmp/test-dpls.hex --erase

# boot UART capture
python3 tools/serial_capture.py 20 --no-reset

# live phone↔board session capture (BLE frames + STATE breadcrumbs)
python3 tools/session_capture/record_session.py --name bringup
# optional: add --serial /dev/ttyUSB0
python3 tools/session_capture/parse_session.py tmp/sessions/session-*-bringup.log
```

- [ ] Плата стартует без watchdog reset-loop; UART показывает нормальный boot.
- [ ] Реклама `Test-DPLS-XXXX` видна; мобильный клиент подключается и проходит аутентификацию.
- [ ] `tmp/sessions/*.ndjson` содержит `ble_tx`/`ble_rx`/`STATE` для последующей доработки симулятора.

## 1. Силовые выходы режимов

Проверять логическим анализатором/вольтметром P31/P32/P33 (ISO) и P14/P16/P17 (KZ). Логика активная «1».

| Режим | ISO_1 P31 | ISO_2 P32 | ISO_T P33 | KZ_1 P14 | KZ_2 P16 | KZ_T P17 |
|---|---:|---:|---:|---:|---:|---:|
| Норма | 0 | 0 | 0 | 0 | 0 | 0 |
| Обрыв +Т | 0 | 0 | **1** | 0 | 0 | 0 |
| Обрыв магистрали | 0 | **1** | 0 | 0 | 0 | 0 |
| КЗ +1 | 0 | 0 | 0 | **1** | 0 | 0 |
| КЗ +2 | 0 | 0 | 0 | 0 | **1** | 0 |
| КЗ +Т | 0 | 0 | 0 | 0 | 0 | **1** |

- [ ] На старте до BLE все шесть выходов = 0.
- [ ] Каждый режим даёт ровно один активный сигнал по таблице.
- [ ] Break-before-make: при переходе между режимами нет перекрытия двух активных выходов.
- [ ] Переключение ≤1 с (ТЗ 4.3.6).
- [ ] КЗ определяется С2000-КДЛ как «Короткое замыкание ДПЛС»; обрывы — как «Нет связи»; после `NORMAL` линия восстанавливается без повреждений (ТЗ 5.1).
- [ ] Сквозное сопротивление в `NORMAL` ≤40 мОм; ток КЗ ≤1 А (ТЗ 4.3.3/4.3.5).

## 2. Светодиод

Зелёный канал RGB — P11. Тайминги задаёт `dpls_led.h`: короткая вспышка 150 мс, пауза 250 мс, длинная 800 мс, межсерийная 1,6 с. Красный P07 и синий P18 во время зелёных сцен должны оставаться выключенными.

- [ ] `NORMAL` от линии — LED выключен.
- [ ] КЗ +1 / +2 / +Т — 1 / 2 / 3 коротких вспышки.
- [ ] Обрыв магистрали — длинная + 2 коротких; обрыв +Т — длинная + 3 коротких.
- [ ] Identify — 1 Гц, duty 50%, auto-stop ≤60 с.
- [ ] Питание от резерва — двойной «тик» в паузе; в `NORMAL` раз в 3 с.
- [ ] Автоизоляция реального КЗ — постоянное свечение.
- [ ] Приоритет: identify > автоизоляция > индикация режима.

## 3. ⚠ Напряжения +1 / +2 / +Т / резерв

ADC-каналы revision 2: +1=P20, +2=P15, +Т=P24, резерв=P23. На голом PB-03F-Kit измерительные входы могут быть плавающими; низкий «резерв» ожидаемо заставляет safety-core немедленно вернуть опасный режим в `NORMAL` (`DPLS_RETURN_LOW_RESERVE`). Полный тест режимов выполнять на силовой части с заряженным резервом.

- [ ] Значение монотонно растёт во всём диапазоне 0…30 В.
- [ ] При 27–30 В нет насыщения ADC; используется обычный режим разрешения, потому что high-res ограничивает верхний диапазон.
- [ ] Выполнить двухточечную калибровку (например 5 В и 27 В) через `dpls_calib_from_two_points`.
- [ ] Записать калибровку в SNV `0x83`; `0x82` зарезервирован под BLE address.
- [ ] После калибровки погрешность ≤±0,1 В в 5…27 В, дискретность 0,1 В (ТЗ 4.3.7 / 5.1f).
- [ ] Без калибровки поведение деградирует безопасно и остаётся диагностически осмысленным.

## 4. ⚠ Резервный ионистор и источник питания

Текущие предварительные пороги: `DPLS_RESERVE_LOW_MV=3700`, `DPLS_RESERVE_OK_MV=4000`, `DPLS_LINE_ABSENT_MV=3000`, `DPLS_LINE_PRESENT_MV=4000`. Фактический коэффициент делителя резерва требуется подтвердить по силовой части.

- [ ] Определить делитель VCAP и скорректировать gain/offset.
- [ ] Проверить рабочее окно резерва примерно 5,0→3,6 В.
- [ ] Низкий резерв переключается с гистерезисом без дребезга.
- [ ] При снятии линии `power_source=RESERVE`, при восстановлении — `DPLS`; журнал содержит событие 12.
- [ ] Автономия от резерва ≥5 мин с BLE (ТЗ 4.4.2 / 5.1d).
- [ ] Средний ток ≤0,5 мА, пики ≤3 мА (ТЗ 4.3.2).
- [ ] Опасный режим автоматически снимается при низком резерве.

## 5. ⚠ Автоизоляция реального КЗ

Firmware-side детект использует просадку линии в `NORMAL`: trip 3000 мВ, release 4500 мВ и условие «сначала увидеть здоровую линию». Требование ≤200 мс относится к аппаратной изоляции силовой части.

- [ ] Реальное КЗ ниже по линии → аппаратная изоляция ≤200 мс, рабочий порог 2,9–3,4 В.
- [ ] Firmware пишет событие 14 / param 1, включает постоянную индикацию и сообщает `real_short`.
- [ ] При активной автоизоляции test-mode команда отвергается кодом 5.
- [ ] После снятия КЗ событие 14 / param 0, индикация снимается и тесты снова доступны.
- [ ] Подтвердить 3000/4500 мВ на реальной силовой части и скорректировать при необходимости.
- [ ] Если в следующей ревизии появится отдельный сигнал «изоляция активна», выделить под него GPIO осознанно: в revision 2 свободного вывода в принятой распиновке нет.

## 6. Заводской сброс

- [ ] P34↔GND ≥5 с очищает имя/пароль и bonds и возвращает устройство в `EMPTY`.
- [ ] P24 нельзя использовать для сброса: это ADC +Т.
- [ ] Удалённый factory reset по BLE отсутствует (ТЗ 7.3.7 / 5.1h).
- [ ] Настройки и калибровка переживают штатные переключения питания (ТЗ 4.4.5).

## 7. ⚠ Заводская калибровка

`dpls_calib_from_two_points` и NV-формат `dpls_calib_nv_t` (SNV `0x83`) реализованы. Заводскому процессу нужен физически контролируемый канал записи.

- [ ] Реализовать/зафиксировать сервисную UART-команду: две точки → gain+offset → SNV `0x83` + CRC.
- [ ] Добавить чтение текущей калибровки для верификации.
- [ ] Если нужен BLE-вариант, разрешать его только в отдельном сервисном режиме, согласованном с заказчиком.
- [ ] После записи повторить раздел 3.

## 8. BLE round-trip

- [ ] `STATE_REPORT` в приложении соответствует фактическим mode/voltage/power/reserve/real-short состояниям.
- [ ] События 12/13/14 и причина автовозврата 7 корректно отображаются в журнале.
- [ ] MODE_SET идемпотентен; safety return работает по таймеру, потере BLE и низкому резерву.
- [ ] После пяти неверных паролей действует lock 300 с.
- [ ] Команды без требуемого шифрования отвергаются (ТЗ 7.3.6).
