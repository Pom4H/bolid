# Финализация Тест-ДПЛС — итог по замечаниям рецензии

Ветка `finalization-pr`, 8 коммитов (этапы 0–7), 2026-07-14. Каждый этап собран,
проверен хостовыми тестами и прогнан на живой плате PB-03F-Kit (BLE-часть).
Силовая часть (ISO/KZ-выходы, реальное КЗ) на железе не проверялась — нет
опытного образца силовой платы.

## Что подтверждено на живой плате

- Честный UI: «Напряжение ДПЛС —», «Источник питания Не определён».
- Персистентная блокировка: 5 ошибок → блок → ребут → SNV `DLCK` locked=1 → вход всё ещё заблокирован.
- Реальные настройки: About = `DPLS-E460E80E` / FW `1.1.0` / протокол 1 / измерение нет / feedback нет; смена имени и пароля с реаутентификацией.
- Транспорт: ~92 log-chunk через очередь без потерь/retry (дренаж по ATT-подтверждению).
- Журнал: 200 записей за 14 батчей ~6 c; ротация snapshot; текущий запуск = календарь (14:20:59), прошлый = `+00:15:14`.
- Идентификация: скан показывает `Test-DPLS-E80E`, device_id совпадает с About.
- Загрузка стабильна (1 REST CAUSE), полный E2E зелёный.

## Открытые / отложенные пункты

- **ADC (п.9)** — главный открытый вопрос. Минимальный ISR не устранил
  watchdog reset-loop (soak: ~9 REST CAUSE за 45 c при `DPLS_ADC_SAMPLING=1`).
  Причина — сосуществование ADC-clock и радио в `adc_kick`, требует
  PHY62xx-специфичного решения (init clock один раз, гейтинг в BLE-idle, другой
  clock-источник). Без ADC напряжение/резерв/автоизоляция не измеряются, флаги
  валидности честно показывают «нет». См. `bring-up-checklist.md` §3.
- **Фрагментация под MTU 23 (п.5)** — отложена; Android всегда договаривается на 247.
- **Аппаратный feedback режима, вариант B (п.10)** — нужен сигнал с силовой платы.
- **Вынос BLE-сессии из BleClient в тестируемый Kotlin (п.12)** — не делалось.
- **Силовая часть** — вся не проверена на железе (нет опытного образца).
