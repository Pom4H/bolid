# Live voltage reporting requirements

## Основание

Исходное ТЗ требует измерять напряжение ДПЛС на клеммах устройства, передавать его через BLE и показывать в мобильном приложении. Для измерительного канала заданы входное сопротивление не менее 1 МОм, диапазон не менее 0–30 В, погрешность не хуже ±0,1 В в диапазоне 5–27 В и разрешение не хуже 0,1 В.

Исходное ТЗ не требует раздельных измерений на +1, +2 и +Т. Этот документ фиксирует дополнительное требование проекта: **четыре независимых live-канала — +1, +2, +Т и резерв**.

## Функциональный контракт

1. После аутентификации одновременно доступны +1, +2, +Т и напряжение резервного накопителя.
2. Значения обновляются автоматически не реже одного раза в секунду во всех режимах, включая `NORMAL`.
3. Wire format использует целые милливольты; UI форматирует их как вольты.
4. У каждого канала отдельный validity-флаг. Ноль без validity не считается подтверждённым измерением.
5. Запрещено подставлять одно измерение в несколько каналов.
6. После трёх пропущенных периодов клиент считает telemetry stale.
7. Опрос может приостанавливаться на время команды/выгрузки журнала и должен автоматически возобновляться.
8. Расширенный `STATE_REPORT` сохраняет 17-байтовый совместимый префикс и добавляет четыре `uint16 LE`: +1, +2, +Т, резерв.

## Revision 2: ADC mapping

PHY6252 использует внутренний ADC-мультиплексор; firmware последовательно сканирует четыре single-ended входа. Source of truth — `firmware/phy6252/dpls_board.h`.

| Измерение | GPIO | PHY62XX SDK channel |
|---|---|---|
| +1 | P20 | `ADC_CH3P_P20` |
| +2 | P15 | `ADC_CH3N_P15` |
| +Т | P24 | `ADC_CH2N_P24` |
| резерв | P23 | `ADC_CH1P_P23` |

Каждая клемма требует собственного измерительного тракта: высокоомный делитель/защита на диапазон 0–30 В и RC-фильтр. Напряжение ДПЛС нельзя подавать непосредственно на GPIO.

Идентичные тракты +1/+2/+Т могут использовать одну схему заводской gain/offset-калибровки, но точность каждого канала проверяется отдельно.

## GPIO coexistence

- P7 / P11 / P18 — RGB R / G / B.
- Identify использует зелёный канал.
- P24 — ADC +Т, не reset.
- P34 — физический factory reset.
- P15 — ADC +2.
- P14 — KZ_1.

Любое изменение mapping должно одновременно менять board config, firmware pinout contract и этот документ.

## Acceptance criteria

1. В `NORMAL` и каждом из пяти тестовых режимов новый state report приходит не реже одного раза в секунду.
2. Validity каждого канала устанавливается только после завершённого преобразования этого входа.
3. Изменение входа появляется в приложении не позднее двух секунд.
4. Клиент продолжает корректно читать legacy 17-byte `STATE_REPORT`.
5. +1, +2 и +Т сверяются с поверенным вольтметром в точках 5, 12, 24 и 27 В; ошибка каждого канала ≤±0,1 В.
6. На железе подтверждается отсутствие GPIO-конфликтов по таблице revision 2.
7. Identify мигает чистым зелёным без примеси красного/синего.

Аппаратная процедура проверки и калибровки приведена в [bring-up-checklist.md](bring-up-checklist.md).
