# Требования к отображению напряжений в реальном времени

## Основание в ТЗ

Исходное ТЗ требует измерять напряжение ДПЛС на клеммах устройства, передавать
его через BLE и показывать в мобильном приложении. Для измерительного канала
заданы входное сопротивление не менее 1 МОм, диапазон не менее 0–30 В,
погрешность не хуже ±0,1 В в диапазоне 5–27 В и разрешение не хуже 0,1 В.

Раздельные +1/+2/+Т являются дополнительным требованием revision 2.

## Функциональные требования

1. После аутентификации одновременно отображаются +1, +2, +Т и резерв.
2. Полный четырёхканальный цикл запускается примерно раз в секунду.
3. По BLE передаются целые милливольты; приложение форматирует вольты.
4. Для каждого канала передаётся отдельный validity-флаг. Ноль без флага не
   является измерением.
5. Запрещено копировать одно физическое показание в несколько каналов.
6. Если канал не выдаёт свежих samples несколько периодов, его validity
   снимается; старое число не должно выглядеть живым.
7. Ошибка одного ADC-канала не должна блокировать обновление трёх остальных.
8. Расширенный STATE_REPORT сохраняет 17-байтовый совместимый префикс и
   добавляет +1, +2, +Т и резерв как четыре `uint16 LE`.

## Аппаратная реализация revision 2

Внешний ADC/мультиплексор не требуется. Встроенный PHY6252 ADC сканируется
строго последовательно, по одному single-ended входу:

| Измерение | GPIO | Канал SDK |
|---|---:|---:|
| +1 | P20 | ADC_CH9 |
| +2 | P15 | ADC_CH4 |
| +Т | P24 | ADC_CH2 |
| резерв | P23 | ADC_CH1 |

У каждой клеммы свой высокоомный делитель/защита/фильтр. Подавать напряжение
ДПЛС непосредственно на GPIO запрещено.

**Калибровка также независимая.** Даже при одинаковых номиналах делителей
+1/+2/+Т имеют разные допуски компонентов, поэтому у каждого канала собственные
`gain/offset`. Legacy-калибровка старых релизов относится только к P20/+1 и не
должна автоматически переноситься на P15/+2 или P24/+Т. Резерв имеет отдельный
делитель и отдельный диапазон допустимого gain.

Флаг `ADC_CALIBRATED` означает, что валидная per-channel калибровка присутствует
для **всех четырёх** входов, а не только для +1.

RGB сохраняется: P7/P11/P18 — red/green/blue. Identify использует P11. P24 —
только +Т ADC, физический reset — P34, P15 — только +2 ADC, P14 — только KZ_1.

## Приёмка

1. В «Норме» и каждом тестовом режиме четыре значения продолжают обновляться.
2. Каждый validity устанавливается только после реального conversion своего
   канала и снимается при устаревании.
3. Изменение каждого входа появляется в приложении не позднее двух секунд.
4. Старый 17-байтовый префикс STATE_REPORT остаётся совместимым.
5. +1/+2/+Т проверяются поверенным вольтметром отдельно в точках 5, 12, 24,
   27 В; ошибка каждого после заводской калибровки ≤±0,1 В.
6. Проверяется отсутствие конфликтов GPIO: P20/P15/P24/P23 =
   +1/+2/+Т/резерв; P7/P11/P18 = RGB; P14 = KZ_1; P34 = reset.
7. Отключение/ошибка одного аналогового входа не останавливает остальные.
8. При identify RGB мигает чистым зелёным без красного/синего канала.
