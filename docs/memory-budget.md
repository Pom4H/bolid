# Бюджет памяти Тест-ДПЛС (базовая линия)

Снято с linker map target-сборки SDK 3.1.2. Актуальный map —
`Firmware/targets/phy6252/out/test-dpls/Target_1/test-dpls.axf.map` (и CI-артефакт).
Цель файла — сравнивать расход после каждого этапа: новые буферы должны уходить
в свободный банк ER_IROM2, а пиковый стек — снижаться, а не расти.

Чип PHY6252: 64 КБ SRAM, 256 КБ flash.

## Узкие места (приоритет оптимизации дня)

1. **ER_IROM1: свободно 1 336 Б (95,6% занято).** Новые крупные буферы (TX-очередь,
   статические frame/ind) размещать секцией в **ER_IROM2** (свободно ~13 КБ).
2. **Куча OSAL 2 КБ при MTU 247.** Отказ аллокации indication = потерянный ответ
   (та же «BLE занят» из п.4). Перенести кучу в свободный банк и расширить.
3. **Стек 2 КБ; в цепочке приёма ~0,9 КБ своих локалок** (`dpls_frame_t` +
   `attHandleValueInd_t`). OSAL однопоточный → сделать статическими (−~490 Б пик).
4. **Write-amplification журнала:** событие 12 Б → перезапись SNV-блока 120 Б
   (подтверждено на железе: `osal_snv_write:a0,120` при BOOT). Кандидат на raw-ring.

## Контрольные точки после этапов

| Этап | Влияние | ER_IROM1 занято (Size) | Проверка |
|---|---|---|---|
| базовая линия | — | 0x7290 (29 328) / 30 664 | — |
| 1 validity | +1 байт payload, +8 Б ZI | 0x7290 | map ✓ |
| 2 auth-lock | +8 Б ZI (2× uint32) | 0x72a0 | map ✓ |
| 3 device info | +16 Б ZI | 0x72b0 | map ✓ |
| 4 транспорт | TX-очередь 4×246 в retained ER_IROM1, RX 4×246→8×98 | 0x75c0 (запас 520 Б) | map + E2E ✓ |
| 6 ADC | float уже в XIP | ~0 | map |

**Заметка по этапу 4:** TX-очередь (≈1 КБ) оставлена в **retained** ER_IROM1, а не
в свободном ER_IROM2 (F1): банк 0x1fffc000 держит DTM-код и его ретенция в
PWR_MODE_SLEEP не подтверждена — очередь, живущая между connection events,
там могла бы теряться при пробуждении. RX-очередь ужата (984→784 Б), чтобы
частично компенсировать. Запас 520 Б — если этап 5/6 не влезет, кандидаты:
уменьшить глубину TX до 3, либо подтвердить ретенцию ER_IROM2 и вынести очередь
туда.
